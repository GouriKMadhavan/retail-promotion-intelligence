The problem

Promotions are judged after the money is spent

Planners work from spreadsheets and instinct. Three costs hide inside a promotion that looks successful.

Wasted discount

A large share of discounted units go to shoppers who would have paid full price anyway.

Cannibalization

The promoted item steals sales from a higher-margin sibling, so basket margin falls while unit sales rise.

Bad timing

A cold drink on promotion during a cold snap, or a promo that collides with Black Friday, under-delivers.

Six strengths

Why this holds up under scrutiny

Most AI demos are a chat box over a model. RPIP is a decision system with checks built in.

Claude decides, code computes

Claude picks comparable promotions, substitutes and verdicts. Python calculators produce every figure. You get readable reasoning and numbers you can audit.

core/calc/*.py · mcp_servers/calc_server.py

An independent critic

The risk critic sees only the outputs, never the other agents' reasoning. That removes anchoring, and it gates every alternative and opportunity.

.claude/agents/risk-critic-agent.md

It fixes, not just flags

A revise verdict triggers three redesigned promotions. Each runs through the full pipeline again and the set is ranked by risk-adjusted margin.

Proactive and pre-vetted

Claude agents

Decide and explain

  • Which past promotions are valid analogs, and why others were rejected
  • Which products are substitutes and which are complements
  • Which demand signals matter, and in which direction
  • The verdict and the named risks
  • Which alternatives to design and recommend
Deterministic tools

Calculate and verify

  • Lift range from the chosen analogs
  • Basket effect from substitute and complement rates
  • ROI, margin impact, wasted discount, break-even lift
  • Money held as integer cents, no rounding drift
  • Missing data becomes "unknown" with lower confidence
See it work

A three-minute walkthrough

The synthetic data has planted scenarios, so the story is reproducible.

  1. Upload a plan

    A CSV with any column names, or a sentence such as "20% off cocoa Dec 6 to 13, 10% vendor funded". Intake resolves messy product names to catalog SKUs and flags ambiguous matches.

  2. Watch the agents work

    Live progress shows each agent as it runs and what it decided.

  3. The trap: a 50% two-for-one on soda

    The critic returns revise: heavy wasted discount and cannibalization of a higher-margin sibling.

  4. The fix

    Three redesigned alternatives, each fully re-evaluated and compared with the original. One is recommended, with the reason the others were not.

  5. The win: a cocoa bundle timed to a cold snap

    Same system, different answer. It is not a tool that says no to everything.

  6. Proactive opportunities

    Ranked ideas built from events, weather, trends and inventory. Each has already passed the critic.

  7. Audit the reasoning

    Open "How Claude decided" for every decision with its rationale, evidence and confidence.

Built with Claude

Claude built it, and Claude runs it

The same agent files that built the product in Claude Code are the ones that run inside it.

Claude Code, end to end

Data generator, calculators, agents, orchestrator, MCP servers, dashboard, tests and documentation were written with Claude Code, guided by a project CLAUDE.md of non-negotiable rules.

Sub-agents, least privilege

Nine agent files, each with its own tool allowlist and a model tier chosen for the job. The critic has no tools at all.

Custom MCP servers

Three stdio servers (retail data, signals, calculators) make every data access explicit and auditable.

Headless Claude Code runtime

Agents can run through claude -p with no API key. A bad JSON reply is repaired by resuming the same session, without redoing tool calls.

Model tiering

Top, mid and fast tiers balance quality, cost and latency. Judgment-heavy agents use the top tier.

Swappable backends

Local, Claude Code, LiteLLM or the Claude API, switchable per agent with one environment variable. Every backend returns the same validated envelope.

Run it

Up in five minutes, no API key

The default local mode runs deterministic agents over a bundled synthetic dataset, fully offline. Requires Python 3.10 or newer.

Windows (PowerShell)

python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
$env:RPIP_SIGNALS = "mock"
streamlit run app/Home.py

macOS / Linux

python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
RPIP_SIGNALS=mock streamlit run app/Home.py

Command line

python evaluate.py "20% off cocoa from Dec 6 to Dec 13, 10% vendor funded"
python evaluate.py samples/promo_01.json
python -m pytest tests

The dashboard opens at http://localhost:8501. Add RPIP_BACKEND=local to evaluate.py for an instant offline run.

What it is not, yet

  • Sales, inventory and basket data are synthetic, so the demo is reproducible and contains no personal data.
  • Lift uses analog reasoning, not a trained causal model. That model is the first roadmap item, with Claude still choosing analogs and explaining.
  • Claude-backed runs are slower than local mode, which stays as the reproducible baseline.
